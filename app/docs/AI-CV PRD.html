AI CV Generator

Two-Week Execution PRD & Task Plan — Phase 1, Production-Ready MVP

10 working days FastAPI PostgreSQL / Neon OpenAI API Hetzner Fixed template → PDF / Word

1. Product Objective

Build a web application that allows clients to submit CV and resume information without creating an account, communicate through an integrated chat, and have the submission processed by an admin or an assigned sub-admin.

The admin retains exclusive control of the core AI instructions and master prompt.

The AI does not generate arbitrary HTML or LaTeX as the primary output. Instead, the pipeline separates content generation from formatting:

Client Data
↓
AI (OpenAI API)
↓
Structured CV JSON
↓
Fixed Template
↓
PDF / Word Export

Fixed templates are more reliable than asking a model to recreate formatting on every run, and they preserve exact spacing, headers, and bullet structure across every generation.

Day 6 — OpenAI Integration

Create a dedicated AI service: services/openai_service.py

  1. Load the active master prompt
  2. Retrieve structured client information
  3. Retrieve the relevant job description
  4. Construct the API request and call OpenAI
  5. Request structured output and validate the returned JSON
  6. Store generation metadata
  7. Send the structured result to the CV renderer

The API key stays server-side in environment configuration, never in frontend code.

10. Important Architectural Decision

One deliberate change from the original interpretation of the initial idea:

Avoid

User Information
↓
Huge Prompt
↓
GPT
↓
"Give me LaTeX"

Build instead

Master Prompt
↓
Client Data → OpenAI API
↓
Structured JSON
↓
HTML
DOCX
LaTeX
↓
PDF
Word
.tex

This delivers the same AI intelligence while separating content generation from document formatting. If the design should change later, the template changes rather than the entire AI prompt.

The research already supports this architecture and specifically recommends keeping the model focused on structured CV content while a developer-controlled template handles exact formatting.

Scope Discipline

Because this is a two-week sprint, SaaS features are not built now just because the product may become SaaS later. The architecture should allow for SaaS growth, but Phase 1 stays focused on the critical product loop:

Submission → Chat → Admin → Assignment → AI → CV → Export

Everything else is secondary.
